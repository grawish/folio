# Whole-profile data retention matrix

Scope: current unsigned development candidate on Apple silicon macOS. Limits are local policy and process-kill evidence, not a whole-device quota, power-loss guarantee, network-filesystem claim, signed-release qualification, or support-device acceptance.

| Store | Limit and retention policy | Review/removal and interruption evidence | Remaining limit |
| --- | --- | --- | --- |
| Save/recovery journals | Transaction records and temporary files live under `workspace-maintenance/` until a project reopen consumes recovery or resumes cleanup. Project/history bounds apply before a transaction writes. | Save transactions preserve recovery at process-kill boundaries; completed recovery unlinks recognized records. `tests/save-transactions.test.ts`, `npm run test:save-recovery`. | No aggregate journal-directory quota; physical power loss and network filesystems untested. |
| Project history | Per project: 1,000 versions, 64 MiB indexed source/PDF, 25 MiB per version, 2,000 messages/notes and 8 MiB workspace JSON. Portable archives: 100 MiB compressed, 200 MiB expanded. | History UI requires explicit review/removal and protects current/newest versions. Count/byte admission, removal and held-write recovery are covered by `tests/history-storage.test.ts`, `tests/workspace-queue.test.ts`, and `npm run test:history-storage`. | Multiple projects have no user-wide quota; power loss during removal untested. |
| Managed compiler identities | Keeps current and previous generation per identity plus active leases. Requires proposed-copy allowance and free-space checks; logical compiler root is bounded to 16 GiB. | Settings removal protects included/current/leased identities; copy, self-test, pointer and removal interruption cases are covered by runtime-manager tests and `npm run test:runtime`. | Production signing, user-wide multi-identity accounting and physical power loss untested. |
| Compiler helper cache | Per work root: two identities, 128 MiB, 4,096 entries and depth eight. Monitor stops an oversized writer; recognized old cache identities evict oldest first. | `tests/engine-cache.test.ts` and real native cache-writer integration controls cover bounds and process cleanup. | No aggregate across work roots; remote filesystems and hostile concurrent writers untested. |
| Resource packs | A pack download is at most 128 MiB; catalog envelope 2 MiB; archive expansion 256 MiB; at most 128 catalog entries. Complete signed archives stay cached for offline reuse. | Settings gives explicit cancellation/cleanup; resume, corruption and staging behavior are exercised by `tests/pack-download.test.ts`, `tests/resource-pack.test.ts`, `npm run test:packs`, and `npm run test:pack-catalog`. | No quota on distinct retained packs; production publisher operations and power loss remain open. |
| App updates | One pending signed ZIP up to 2 GiB plus bounded metadata. Preflight checks `2 × ZIP + 3 × unpacked + 1 GiB` before download/staging. | Retry/obsolete-file cleanup and interrupted transfer tests cover unsigned development workflows. `npm run test:updates`, `npm run test:update-download`. | Signed-to-signed updates, physical low-disk/power-loss behavior and production publisher acceptance remain open. |
| Build workspaces | Owned `.folio-build-jobs-v1/job-*` workspaces are released after builds; startup reclaims verified dead owners and preserves unrecognized/doubtful data. | Process-kill build-recovery controls test staging, exit, cleanup and safe preservation of unrelated files. `tests/build-workspaces.test.ts` and integration build-recovery tests. | No aggregate per-job quota; power loss, PID-reuse long sessions and network filesystems untested. |
| AI temporary sessions | Request directories are removed in provider `finally` paths; a Codex session has a 60-second idle timeout. | Local protocol/chat fixtures exercise request completion and errors. | No explicit request-directory quota or dedicated abnormal-cleanup control; real providers are separately blocked. |
| Preferences | `workspace-preferences.json` is a validated 2 KiB atomic record, retained across sessions. | Preference persistence and failure paths run in desktop workflows. | No network-filesystem/power-loss acceptance.

## Accounted growth and remaining scope

The current 120-cycle process profile records unchanged runtime/build logical bytes across its 14 storage observations. The 29 September three-sample storage repeat preserved source/PDF/version data through 100 histories; at 100 histories the workspace is about 2.69 MiB and the history archive about 2.54 MiB. See `PERFORMANCE_IMPROVEMENT_PLAN.md#save-and-history-growth`.

The stores above have bounded local policy or explicit user review where they retain data. Folio does not impose a single user-wide quota across all projects, runtimes, packs, updates and temporary data. That absence, plus physical power loss, supported filesystems, signed releases and long-duration multi-project measurements, keeps PERF-07 open.
